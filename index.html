Methodology

This page explains how the Urban Clearance Planner generates tasks, scores them, and produces the clearance schedule.

Task identification

Every task ID follows the format ORG-TO-NTS-SEQ.

PartMeaningExample
ORGOrganisation code, set in Task ID settingsORG or LMAC
TOTask order code, set in Task ID settingsTO or TO01
NTSTask type code (see below)EOD
SEQThree digit sequence number, numbered per task type001, 002, 003

Task type codes:

CodeMeaningSource layer
EODExplosive Ordnance DisposalEO items (live only)
RRRubble Inspection and RemovalRubble fields
MBACMechanical Clearance (route or combined)Road segments and combined building plus rubble tasks
BCBuilding ClearanceBuilding levels (damaged, or with a live EO, or with confirmed contamination)

Examples:

ORG-TO-EOD-001   First EO disposal task under task order TO
ORG-TO-RR-001   First rubble inspection and removal task
ORG-TO-MBAC-001   First mechanical clearance task
ORG-TO-BC-001   First building clearance task

How tasks are generated

  • One task per live EO item. Items already destroyed or removed (uxo_status_code is DES) are not tasked.
  • One task per rubble field that is not already released or under clearance.
  • One task per road segment that is blocked or partially blocked and not already cleared.
  • One task per damaged building: damage D2 or worse, or containing a live EO item, or with confirmed or suspected contamination. If the building has rubble on the same source, it becomes a combined clearance task.

How road blocking is computed

Road blocking is a geometric question. The planner does not rely on the blocks_road flag in the source layer as the primary signal. Instead it checks every rubble polygon and every damaged building footprint against every road segment using a bounding box pre-filter followed by exact segment-to-polygon intersection.

  • Rubble blocks a road if its polygon intersects that road segment. If the source layer sets blocks_road to true, that is also respected as an explicit override.
  • Buildings block a road only if their damage is D2 (moderate damage) or worse and their footprint intersects that road segment. Intact buildings that abut a road do not block it.
  • Only the specific roads that are intersected receive the dependency. There is no "nearest road within 40 m" fallback.

How each task is scored

Every task gets five independent scores from 0 to 100:

  • Threat risk. How dangerous the item is today. Data confidence is shown separately and never raises risk. A missing survey date counts as stale.
  • Impact. What clearance achieves.
  • Access enabler. The impact of all tasks it unlocks, counted once each. The number of unlocked tasks is applied only in the unlock boost, to avoid counting it twice.
  • Urgency. Time pressure. Driven by stale surveys, high hazard level EO, and buildings with no safe access.
  • Efficiency. Impact per estimated hour, scaled against the 90th percentile task so one trivial task does not flatten the rest.

How priority is calculated

Base priority is a weighted sum of the five scores. The default weights are shown in Tasking parameters and can be adjusted:

base_priority = (0.30 x threat_risk + 0.25 x impact + 0.20 x access_enabler + 0.15 x urgency + 0.10 x efficiency) / sum_of_weights

Operational priority then amplifies any task that unlocks other tasks:

operational_priority = base_priority x (1 + boost x log2(1 + unique_downstream_tasks)), boost = 0.15 by default

Task dependencies

  • An EO item inside a building, road, or rubble becomes a precondition.
  • Any rubble, building or road task within the EO standoff distance (default 50 m) of a live EO item waits until that item is disposed of. Set the standoff to 0 to turn this off.
  • Rubble or a damaged building that physically intersects a road segment becomes a precondition for that specific road task.
  • Rubble that belongs to a destroyed building becomes a precondition for the building task.

Scheduling

  • Clearance elements are read from Tasking parameters. Each element type (EOD, mechanical, hazmat, structural) is scheduled independently.
  • Tasks are assigned to the least loaded element of the right type.
  • A task only starts when all of its dependencies are complete.
  • Within the set of tasks that can start at any moment, the highest operational priority goes first.

Effort estimates

  • Rubble: 0.5 hours per cubic metre of volume, plus 2 hours per metre of height.
  • Buildings: 0.3 hours per square metre per level, multiplied by a damage factor (0.3 for D0 up to 1.5 for D5).
  • Road segments: 0.2 hours per linear metre, plus 0.5 hours per metre of width.
  • EO items: 4 hours base, plus 2 hours per metre of burial depth, plus 4 for aircraft bombs, plus 2 when the item is in rubble.

Contamination report

The Contamination tab summarises the loaded layers without scoring them. Buildings are grouped by contamination type with footprint area and floor area (footprint x levels). Rubble fields are grouped by type with volume. EO items are summarised by class, status, hazard level and location. Contaminated means confirmed or suspected. Records with no type are shown as None identified.

What the planner does not decide

  • It does not recommend between stabilising and demolishing an unsafe building with EO inside.
  • It does not certify clearance. QA and release remain separate workflows in IMSMA Core.
  • It does not account for travel time between tasks, crew rest cycles, or seasonal constraints.
